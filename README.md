# Legal Topic Sorter

A FastAPI application that clusters US Supreme Court opinions into topics, builds a similarity graph for finding related cases, and measures how much the two approaches agree. It includes an interactive map of the corpus, semantic search, and optional Claude-written topic names.

## What it does

1. **Downloads** Supreme Court opinions and their official syllabi from the [CaseSumm](https://huggingface.co/datasets/ChicagoHAI/CaseSumm) dataset (100 bundled; thousands more on request)
2. **Embeds** each full opinion with `all-MiniLM-L6-v2`, in overlapping 240-token windows averaged into one vector per case
3. **Clusters** them into topics using BERTopic (UMAP + HDBSCAN + c-TF-IDF)
4. **Builds a similarity graph** (percentile threshold + k nearest neighbours) and finds communities with Louvain
5. **Compares** the two groupings (ARI / NMI, contingency table, per-case disagreements)
6. **Serves** an explorer UI, semantic passage search and a REST API

## Two approaches to grouping documents

### BERTopic (topic modeling)

Answers: *"What distinct topics exist in this corpus?"*

- Embeddings are compressed to 5 dimensions via UMAP (non-linear dimensionality reduction)
- HDBSCAN finds dense regions in that reduced space; cluster size scales with the corpus
- c-TF-IDF extracts distinguishing keywords per topic (unigrams and bigrams, with generic legal words like "court" and "judgment" removed)
- Outliers are reassigned to their nearest topic and keywords are recomputed afterwards

### Similarity graph + Louvain (community detection)

Answers: *"Which documents are most connected to each other?"*

- Pairwise cosine similarity is computed in the full 384-D embedding space (no reduction)
- Edges join the top 5% most similar pairs **and** each document's 3 nearest neighbours. A cut-off alone left ~30% of cases with no edges at all, each becoming a one-case "community"
- Louvain finds tightly-knit communities by optimizing modularity

The two methods agree on clearly distinct areas (patents, municipal bonds) but diverge where legal language overlaps; the explorer's **Disagreements** view highlights exactly those cases.

## Explorer

`http://localhost:8000/` opens an interactive map: every dot is a case, placed by a 2-D UMAP projection so nearby cases read alike.

- **Color by** BERTopic topic, Louvain community, or **Disagreements** (cases whose topic differs from the majority of their community)
- Click a dot for the syllabus, its topic and community, and its most similar cases
- Click a legend chip or topic row to isolate it; the topic × community heatmap shows how each topic splits across communities
- Search in plain language ("ship cargo damaged in a storm"); results show the best-matching passage
- `?q=...` and `?doc=...` in the URL link straight to a search or a case

## Semantic search

`GET /search?q=...` embeds the query and compares it against every chunk of every opinion, so a case ranks by its single best-matching passage, which is returned as the snippet. This finds cases by facts or doctrine buried deep in long opinions, which whole-document vectors blur away.

## Readable topic names (optional)

BERTopic labels topics with keywords ("patent / invention / claim"). Set `ENABLE_LLM_LABELS=1` and Claude names each topic from its keywords and representative syllabi in one request (e.g. "Patent infringement on industrial machinery"). It is off by default because it calls a paid API.

- Uses the Anthropic SDK; credentials come from `ANTHROPIC_API_KEY` (or an `ant auth login` profile)
- Model is `claude-opus-5-5` by default (`LLM_LABEL_MODEL` to change), at low effort, with structured JSON output
- Labels are cached in `.cache/` by topic content, so restarts cost nothing; any failure falls back to keyword labels

## API endpoints

### Topics (BERTopic)

| Endpoint | Description |
|---|---|
| `GET /clusters` | All topics with label, size, keywords, representative docs |
| `GET /clusters/{id}` | Topic detail with all member documents |
| `GET /documents/{id}` | Single document with syllabus, topic and community |

### Search and similarity

| Endpoint | Description |
|---|---|
| `GET /search?q=...&top_k=10` | Semantic passage search |
| `GET /documents/{id}/similar?top_k=10` | Most similar documents by cosine similarity |

### Similarity graph

| Endpoint | Description |
|---|---|
| `GET /graph/info` | Nodes, edges, density, communities, modularity, threshold |
| `GET /graph/stats` | Similarity distribution (min, max, percentiles) |
| `GET /graph/communities` | All Louvain communities (largest first) |
| `GET /graph/communities/{id}` | Single community's members |
| `GET /graph/edges?min_weight=&limit=100` | Strongest similarity edges |
| `GET /graph/export?max_edges=4000` | Map positions, both groupings and edges in one payload (used by the explorer) |

### Analysis and other

| Endpoint | Description |
|---|---|
| `GET /analysis/comparison` | ARI / NMI between topics and communities, contingency table, disagreeing cases |
| `GET /health` | Status check |
| `GET /docs` | Interactive Swagger UI |

## Setup

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt

uvicorn app:app --reload        # open http://localhost:8000
pytest                          # ~20s, no model downloads
```

The first start embeds the corpus and fits the models (about 30s for 100 cases); results are cached in `.cache/`, so later starts take a few seconds.

### More data

The bundled file has the first 100 cases in the dataset, mostly from the 1880s. For a broader corpus:

```bash
python download_docs.py --num-docs 1000 --sample --out data/sample_1000.jsonl
DOCS_PATH=data/sample_1000.jsonl uvicorn app:app
```

### Docker

```bash
docker build -t legal-topic-sorter .
docker run -p 8000:8000 legal-topic-sorter
```

The image bakes in the embedding model and precomputed results, so it starts in seconds without network access.

### Configuration

All optional, via environment variables:

| Variable | Default | Meaning |
|---|---|---|
| `DOCS_PATH` | `data/documents.jsonl` | Corpus file |
| `CACHE_DIR` | `.cache` | Embedding, topic and label cache |
| `EMBED_MODEL` | `all-MiniLM-L6-v2` | Any sentence-transformers model |
| `EMBED_STRATEGY` | `chunked` | `chunked` (whole opinion) or `truncated` (first ~256 tokens, the original behaviour) |
| `SIM_PERCENTILE` | `95` | Pairs above this percentile of similarity become edges |
| `SIM_THRESHOLD` | unset | Fixed similarity cut-off; overrides the percentile |
| `SIM_KNN` | `3` | Nearest-neighbour edges added per document |
| `ENABLE_LLM_LABELS` | off | Claude topic names |
| `LLM_LABEL_MODEL` | `claude-opus-5-5` | Model for topic names |

## Project structure

```
app.py              — FastAPI routes and startup
pipeline.py         — Builds and caches everything the API serves
config.py           — Settings from environment variables
data_loader.py      — Document loading, chunking and embedding (with cache)
topic_modeling.py   — BERTopic configuration, topic extraction, 2-D projection
similarity.py       — Similarity graph and Louvain communities
evaluation.py       — Metrics: self-retrieval, coherence, agreement, stability
evaluate.py         — CLI that writes the reports in reports/
labeling.py         — Optional Claude topic names
download_docs.py    — Dataset downloader (CaseSumm from Hugging Face)
static/explorer.html— Explorer UI
tests/              — pytest suite (uses a fake embedder; no downloads)
```

## Dataset notes

CaseSumm provides only a citation, the syllabus and the opinion text: there are no case names or decision dates. Titles are formatted citations (`108 U.S. 30`); `date` is filled only for recent cases whose citation carries a term year.
